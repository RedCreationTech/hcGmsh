## 1. 范围与红线

### 1.1 总任务池

1. 修复 `ProjectDocument` 乱序装载、深层层级、顺序保持和失败原子性合同。
2. 为 schema v2 模型对象增加向后兼容的持久 `id`。
3. 让 `ProjectStore` 直接装载/保存 `ProjectDocument`，取消持久化对 Tree 的依赖。
4. 建立以 ObjectId 为目标的最小领域命令集。
5. 反转 `ModelTreeAdapter`：Document 写入，Tree 投影。
6. 把 stale 传播升级为对象级图，并把 CAE 兼容规则移出 `hc_core`。
7. 在命令覆盖完整后增加内部 Undo/Redo 栈；本轮默认不开放新的 UI 入口。

当前 v0.2.1 核心切片只执行第 1～5 项；第 6 项在 G4 前执行，第 7 项在 Feature Graph 前执行。

### 1.2 不在本轮

- 不新增 UI 功能、节点类型、MOOSE 映射或 G2/G3 算例。
- 不升级到 schema v3；只增加 schema v2 可选字段。
- 不一次性重写全部 name reference；采用兼容读取、渐进写入 ObjectId。
- 不拆分 `gmp_ise_phase0_test`。当前测试不足 1 秒，等用例归属或耗时成为真实问题再拆。
- 不进行 `hc_project/hc_cad/hc_execution/...` 全量目标与目录重排。
- 不重写 `VtkViewer`、`ViewportInternal.h` 或引入 Gmsh 多 Session。
- 不在真源反转前实现 Feature Graph、Headless API 或 AI Agent 写模型能力。

### 1.3 回归红线

- `.gmp.yaml` schema v2 旧项目继续可读；保存重开不丢字段、不改语义。
- G1 `.i` 与既有基线逐字一致；Snapshot manifest 仅允许既有时间字段差异。
- 114 步真实点击巡览基线只增不减。
- 项目保存失败、文档装载失败不得破坏内存中的当前项目。
- rename 不改变对象 ID；duplicate 必须获得新 ID；delete + recreate 不复用旧 ID。

## 4. Stage H1：核心合同与持久身份

### TASK-HARD-010 修正 ProjectDocument 装载合同

- **优先级**：P0。
- **关联问题**：复核文档 P1“乱序加载”；当前 `from_variant_list()` 虽称两遍装载，实际仍按输入顺序调用要求父对象已存在的 `addObject()`。
- **涉及路径**：`include/gmp/ProjectDocument.h`、`src/ProjectDocument.cpp`、核心合同测试。
- **实现边界**：
  1. 支持 child-before-parent 与任意深度层级。
  2. 拒绝重复 ID、缺失 parent、自引用和层级环。
  3. 保持 root 与同父子对象的输入顺序；不得按随机 UUID 改变 Step/Feature 等语义顺序。
  4. 使用临时文档完成校验，全部成功后再替换当前文档；失败时原文档不变。
  5. `to_variant_list()` 按层级稳定遍历，不再依赖 UUID 字典序表达业务顺序。
- **最小自动检查**：一个核心合同用例覆盖 child-before-parent、三层树、环拒绝、失败不改原文档、round-trip 顺序一致。
- **准出**：注释中的“允许条目乱序”与真实行为一致，现有 ProjectDocument 合同不退化。
- **执行记录**：✅ 2026-09-20 完成。`from_variant_list()` 改为在临时容器中解析、校验缺失父/重复 ID/自引用/环并统计根可达性，成功后一次性交换状态；`to_variant_list()` 按根与同父挂载顺序做层级先序输出。`test_project_document_contract` 增加 child-before-parent、三层树、顺序 round-trip 和失败原子性断言。验证：构建通过，CTest `1/1` 通过，114 步真实点击巡览 exit=0 无 `FAILED`。

### TASK-HARD-020 schema v2 持久 ObjectId

- **优先级**：P0。
- **依赖**：TASK-HARD-010。
- **关联问题**：当前 `<根名>/<对象名>` 在 rename 后变化，不是稳定身份。
- **涉及路径**：`ProjectDocument.*`、`ModelTreeAdapter.*`、`ProjectStore.*`、`ProjectSchema.*`、`doc/schema/project-v2.md`、合同测试。
- **实现边界**：
  1. schema v2 每个模型对象增加可选 `id`；旧文件无 `id` 时加载期生成 UUID，首次保存时持久化。
  2. 固定根节点使用确定性保留 ID（建议 `root:<kind>`），不要求在 YAML 的对象列表中重复保存。
  3. Tree 增加专用 ObjectId Data Role；名称和 ID 分离。
  4. rename 保持 ID；duplicate 生成新 ID；delete + recreate 生成新 ID。
  5. 同一会话内旧项目即使尚未保存，rename 也不得导致已生成 ID 改变。
- **兼容策略**：继续写 `schema_version: 2`；未知 `id` 字段不影响旧字段解释，不迁移现有 name reference。
- **最小自动检查**：旧 v2 无 ID加载→生成 ID→保存→重开 ID 一致；rename/duplicate/delete-recreate 身份合同。
- **准出**：正常业务路径不再调用 `ModelTreeAdapter::id_for_path(root, name)` 生成对象身份。

### TASK-HARD-030 ProjectStore 与 ProjectDocument 直接互转

- **优先级**：P0。
- **依赖**：TASK-HARD-020。
- **关联问题**：`MainWindow::load_project/save_project` 仍手工在 `ProjectModelEntry` 与 QTreeWidget 之间搬运模型数据。
- **涉及路径**：`ProjectStore.*`、`ProjectDocument.*`、`MainWindow.cpp`、项目持久化合同测试。
- **实现边界**：
  1. `ProjectStore` 的模型载荷直接转换为 `ProjectDocument`；面板 settings、mesh snapshot 等非模型元数据继续保留在 `ProjectData`。
  2. 保存从 Document 序列化模型，不再遍历 Tree 收集业务字段。
  3. 保持全部空根节点、根顺序、对象顺序、typed scalar、Save As 网格迁移和派生文本路径替换语义。
  4. 加载失败不替换当前 Document；写盘采用现有安全边界，不顺带引入新存储框架。
- **最小自动检查**：现有 `test_project_store_contract` 增加 ID、层级、顺序与旧文件迁移断言。
- **准出**：`MainWindow::save_project()` 中不存在遍历 QTreeWidget 组装 `ProjectModelEntry` 的代码；保存重开相关定向巡览全绿。

## 5. Stage H2：Document 真源反转

### TASK-HARD-040 建立最小领域命令集

- **优先级**：P0。
- **依赖**：TASK-HARD-030。
- **目标**：先让领域修改可逆，再把 UI 写路径切过去；不在 Tree 闭包命令上继续堆补丁。
- **涉及路径**：`ProjectDocument.*`、`TransactionManager.*`、核心合同测试。
- **命令范围**：
  - `CreateObjectCommand`
  - `DeleteObjectCommand`（保存完整子树、父 ID 与同级位置）
  - `RenameObjectCommand`
  - `SetPropertiesCommand` 或最小等价实现
  - `SetStatusCommand`
- **实现边界**：
  1. 命令只持有 Document/ObjectId/值，不捕获 `QTreeWidgetItem*`。
  2. execute/revert 任一失败必须可报告；事务不能把半执行命令记为成功。
  3. 删除回放必须恢复完整子树及顺序，不能沿用当前“只恢复本节点”的闭包。
  4. 本任务只做领域命令和服务级测试，不接 UI、不增加菜单。
- **最小自动检查**：五类命令各做一次 execute→revert→execute，最终序列化结果与预期一致。
- **准出**：核心可逆操作不依赖 Widgets；`ClosureCommand` 不再作为模型 CRUD 的正式实现。

### TASK-HARD-050 反转 ModelTreeAdapter 与全部领域写路径

- **优先级**：P0，本轮核心任务。
- **依赖**：TASK-HARD-040。
- **涉及路径**：`ModelTreeAdapter.*`、`MainWindow.*`、`PropertyEditor.*`、`FloatingPropertyForm.*`、相关定向巡览。
- **实现边界**：
  1. Adapter 持有或引用当前 Document，并从 Document 递归构建/更新 Tree。
  2. 新建、复制、重命名、删除、属性提交、状态变化先执行领域命令，再刷新对应投影。
  3. PropertyEditor 以 ObjectId 找对象并写 PropertyBag；Tree Data Role 仅作显示缓存，不再作为业务真源。
  4. 持久化、MOOSE 生成、工作流校验、Assembly 规格和 stale 修改从 Document/纯数据快照读取；UI 导航、展开、选中仍可读 Tree。
  5. 支持任意深度投影；删除 `rebuild_from_tree()` 的正常业务调用，迁移完成后删除该反向重建实现。
  6. 不引入通用 Event Bus；优先用最小的 Document 变更通知或命令完成后的定向投影更新。
- **迁移顺序**：CRUD → 属性表单 → 状态写入 → 生成/校验读取 → 持久化读取；每一步均保持可运行。
- **最小自动检查**：扩展 `model_tree_projection_contract`，覆盖三层结构、rename ID 不变、属性提交、子树删除、保存重开及 G1 `.i` A/B 一致。
- **准出判据**：
  - 正常业务路径的数据流为 `Command -> ProjectDocument -> ModelTreeAdapter -> QTreeWidget`。
  - 不再存在 `Tree -> rebuild_from_tree() -> Document` 业务路径。
  - `record_committed("property form commit", ...)` 被真实命令提交替代。
  - `collect_model_entries()` 不再遍历 Tree 为生成器或持久化提供领域数据。

## 6. Stage H3：对象级依赖与回放

### TASK-HARD-060 DependencyGraph 对象化并移除 core 边界泄漏

- **优先级**：P1。
- **依赖**：TASK-HARD-050。
- **涉及路径**：`DependencyGraph.*`、应用侧 graph builder、`MainWindow::invalidate_downstream_from()`、合同测试、CMake。
- **实现边界**：
  1. `hc_core` 的 `DependencyGraph` 只保留通用图算法，不 include `ProjectSchema`，不包含 CAE 根节点规则。
  2. 应用兼容层根据当前 Document 构建 `ObjectId -> ObjectId` 边。
  3. 第一版先用对象化的 legacy 规则保持现有传播集合，再对已有明确引用逐步收窄：Sketch→Part/Feature、Part→Assembly、Material→Section、Mesh→Input Case→Job 等。
  4. name reference 尚未迁完时允许解析为 ObjectId 后建边；无法解析必须产生可诊断问题，不静默绑定同名对象。
  5. stale 状态先写 Document，再投影 Tree；运行中/排队中/提交中的 Job 过滤语义保持。
- **最小自动检查**：两个同 kind 对象只修改其一时，显式引用链上的对象 stale；不相关兄弟对象不 stale；legacy 场景传播集合不退化。
- **准出**：`legacy_stale_rule_edges()` 不在 `hc_core`；`hc_core` 不再因该实现依赖 `ProjectSchema/yaml-cpp`。

### TASK-HARD-070 内部 Undo/Redo 栈

- **优先级**：P1。
- **依赖**：TASK-HARD-060。
- **目标**：兑现 v0.2 顺延的事务回放能力，但默认只交付内核，不新增用户入口。
- **涉及路径**：`TransactionManager.*`、领域命令、核心合同测试。
- **实现边界**：
  1. committed transaction 进入 undo stack；新提交清空 redo stack。
  2. undo 逆序 revert，redo 顺序 execute；失败不得破坏栈一致性。
  3. audit log 区分 commit/undo/redo；设置合理的内存上限，超限淘汰最旧事务即可。
  4. 仅用户可编辑模型操作进入回放栈；网格运行进度、远程 Job 状态、Results 登记等外部/运行态更新不进入 undo。
  5. 本轮不改变 Sketch 编辑器已有撤销语义，不接 Ctrl+Z/Y。
- **最小自动检查**：create→rename→set properties→delete 的连续 undo/redo；新提交清空 redo；失败命令保持文档与栈不变。
- **准出**：所有入栈模型操作均由可逆领域命令执行，不存在事后审计伪装成可撤销操作。

### Q-H02 持久 ID 是否升级 schema v3？

- **依赖**：Q-H01；决定 HARD-020 的兼容方式。
