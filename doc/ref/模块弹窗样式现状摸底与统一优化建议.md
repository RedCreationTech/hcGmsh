# 模块弹窗样式现状摸底与统一优化建议

> 日期：2026-09-24
> 基线：`main@d607d62`
> 目的：在 V02 开发前，统一左侧模块树 13 个模块弹出工作窗/属性表单的样式与交互。本文先以截图摸清现状，再基于现状给出统一/优化项清单。
> 采集方式：`GMP_UI_AUDIT=1 GMP_SCREENSHOT_DIR=<dir> ./build/gmp_ise`，共 42 张截图（存于 `doc/ref/images/ui-audit/`），逐 TAB 抓取，可复现。

## 0. 总体结构（现状架构）

| 类别 | 模块 | 容器 |
|---|---|---|
| 共享模块工作窗（9 模块共用 `moduleWorkspaceWindow`） | Sketch / Part / Property / Material / Section / Assembly / Step / Interaction / Load | `property_stack_` 切页，9 页同模板 |
| 专属工作窗 | Mesh（GmshPanel） | `gmshWorkspaceTabs`：模型 / 几何（基元/变换/布尔）/ 分组与网格场（物理组/网格场）/ 网格 |
| 专属工作窗 | Job | `jobWorkspaceTabs`：作业列表 / MOOSE 设置（算例设置 / 执行配置 / 输入文件（生成输入/自定义块/生成报告）） |
| 专属工作窗 | Visualization | 下拉+堆叠页：标量 / 网格 / 视图 / 时间 / 变形 |
| 专属工作窗 | Results | `resultsWorkspaceTabs`：结果 / 曲线 / 表格 |
| 跨模块模态表单 | 树节点双击弹出 | `FloatingPropertyForm`：常规 / 参数 / 校验 / 预览 |

## 1. 共享模块工作窗（9 模块）

通用骨架：顶部操作按钮行 +「当前条目:」列表 + 底部「打开所选/重命名/复制/删除」+ 右侧「刷新」。

### 1.1 Sketch（草图页）— 布局异类，问题最多

![audit_module_sketch](images/ui-audit/audit_module_sketch.png)

- 顶部两个通栏大按钮（新建草图 / 打开编辑），与其他页左对齐小按钮风格完全不同。
- 内容只占窗口上部约 40%，下半窗全空白；按钮行浮在中部而非底部。
- 缺少「打开草图根节点」按钮，底部缺少「打开所选草图」，模板不一致。

### 1.2 Part（部件页 + 特征 TAB ×4）

![audit_module_part](images/ui-audit/audit_module_part.png)

| TAB | 截图 |
|---|---|
| 拉伸 | ![audit_part_extrude](images/ui-audit/audit_part_extrude.png) |
| 旋转 | ![audit_part_revolve](images/ui-audit/audit_part_revolve.png) |
| 放样 | ![audit_part_loft](images/ui-audit/audit_part_loft.png) |
| 扫掠 | ![audit_part_sweep](images/ui-audit/audit_part_sweep.png) |

- 参数面板固定高度不随内容自适应（拉伸 2 行、旋转 1 行，下方均留约 100px 空白）。
- 4 个 TAB 标签列宽不一致（「草图:」~75px vs「轮廓草图:」~110px），切换 TAB 时输入框位置跳动。
- 数值框通栏拉满（~1900px），与常规软件窄宽数值框惯例不符；单位英文缩写（mm/deg）。
- 「放样 (实体)」半角括号限定词与其他按钮文案风格不统一。

### 1.3 Property（共享属性编辑器 4 TAB）

![常规](images/ui-audit/audit_property_general.png) | ![参数](images/ui-audit/audit_property_parameters.png) | ![校验](images/ui-audit/audit_property_validation.png) | ![预览](images/ui-audit/audit_property_preview.png)

- 标题整段英文（`Materials — diffusion`）；校验 TAB 空态英文「No validation issues.」，而浮动表单版却是中文「无校验问题。」——同一状态两套文案。
- 常规/校验 TAB 内容仅占顶部一小条，下方 50~75% 空白。
- 「状态 -」「摘要 -」用半角连字符表示空值，与其他模块「暂无XX。」中文空态不一致。

| 模块 | 截图 |
|---|---|
| Material | ![audit_module_material](images/ui-audit/audit_module_material.png) |
| Section | ![audit_module_section](images/ui-audit/audit_module_section.png) |

- 条目统一为 `名称 (英文MOOSE类名)` 格式（如 `diffusion (GenericConstantMaterial)`、`u_dt (TimeDerivative)`），中文界面下术语不可读。

- Step 页预览框整段英文（"Executioner uses the first step only."），参数串直出 MOOSE 语法（`type=Transient dt=0.01`）。
- 底部按钮宽度随文案伸缩，「删除」与「刷新」之间各页均有 1100px+ 空白。

## 2. Mesh 工作窗（7 TAB）

| TAB | 截图 |
|---|---|
| 模型 | ![audit_mesh_model](images/ui-audit/audit_mesh_model.png) |
| 几何 › 基元 | ![audit_mesh_geometry_primitives](images/ui-audit/audit_mesh_geometry_primitives.png) |
| 几何 › 变换 | ![audit_mesh_geometry_transform](images/ui-audit/audit_mesh_geometry_transform.png) |
| 几何 › 布尔 | ![audit_mesh_geometry_boolean](images/ui-audit/audit_mesh_geometry_boolean.png) |
| 分组与网格场 › 物理组 | ![audit_mesh_groups_physical](images/ui-audit/audit_mesh_groups_physical.png) |
| 分组与网格场 › 网格场 | ![audit_mesh_groups_fields](images/ui-audit/audit_mesh_groups_fields.png) |
| 网格 | ![audit_mesh_mesh](images/ui-audit/audit_mesh_mesh.png) |

- **按钮宽度规范混乱（本窗最严重）**：「刷新」在物理组页是通栏、在网格场页是小按钮；「拾取」在布尔/变换页通栏（~1900px）、在其他页贴输入框小按钮；「添加基元/平移/旋转」通栏 vs「合并/剪切/求交」小按钮。
- 参数命名四套风格：平移 `dx/dy/dz`、旋转「旋转原点 x / 旋转轴 ax」、缩放「缩放中心 x / sx」、基元「原点/基点 x / 尺寸/轴 dx」。
- 「维度」下拉取值表示不一致：「全部」/「3」/「0 — 点」/「1」混用。
- 未本地化英文散落：`No geometry loaded`、占位符、下拉项「线性 (I)」。
- 「拾取」一词两义：Mesh 窗=视图中点选实体；Job 设置页=浏览文件。
- 网格场页「实体」标签与输入框之间有约 120px 异常垂直空隙（疑似布局 bug）。
- 各表单结束后大片空白，无底部操作区。

- 生成报告页截图分辨率明显低于其他页（窗口尺寸不统一），映射行尾部出现空的 `(Physical Group=)`。

## 6. 浮动属性表单（FloatingPropertyForm，4 TAB）

![常规](images/ui-audit/audit_form_general.png) | ![参数](images/ui-audit/audit_form_parameters.png) | ![校验](images/ui-audit/audit_form_validation.png) | ![预览](images/ui-audit/audit_form_preview.png)

- **与共享属性编辑器（§1.3）是同一套 4 TAB，但视觉是两套体系**：页签（经典凸起式 vs 圆角蓝字下划线）、按钮（直角白底 vs 圆角浅灰）、复选框（原生灰 vs 蓝色 accent）、「预览」控件（按钮 vs 链接式）全不同。
- 同一节点校验空态：编辑器版英文「No validation issues.」vs 表单版中文「无校验问题。」。
- 预览文本区尺寸策略不同：编辑器版完整显示，表单版出现滚动条且裁掉末行。
- 校验 TAB 结果文字垂直居中于超高空白框，复选框/按钮压在框底，与表单底部「取消/确定」形成两条按钮带。

## 7. 统一/优化项清单（基于现状的分析）

按主题归并，标注建议优先级（P0 = 功能/观感硬伤，P1 = 一致性，P2 = 打磨）。

### 7.1 语言与文案（P0/P1）

| # | 问题 | 位置 | 建议 |
|---|---|---|---|
| L1 | 漏翻英文按钮 `Open Selected instance` | Assembly 页 | 改「打开所选实例」，全应用扫描硬编码英文 |
| L2 | 未本地化占位符/状态 | Mesh 模型页 `No geometry loaded`、Job `(no job submitted)`、自定义块占位符 | 入 l10n 管线 |
| L3 | 条目显示 `名称 (英文MOOSE类名)` | 材料/载荷/分析步等模块页列表 | 增加中文类型映射表（如 TimeDerivative→时间导数项），或至少 tooltip 中文说明 |
| L4 | 校验空态两套文案 | 编辑器「No validation issues.」vs 表单「无校验问题。」 | 统一中文，同一数据源 |
| L5 | 页内整段英文 | Step 预览框、属性页标题 `Input Cases`、预览 TAB 标题/正文 | 预览类内容可保留英文但加中文引导；标题/状态本地化（Generated→已生成） |
| L6 | 中英混排标点 | 半角冒号/括号/连字符混用（「待应用选择:」「放样 (实体)」「摘要 -」） | 统一全角标点；空值用「—」或「暂无」 |

### 7.2 布局与空白（P0/P1）

| # | 问题 | 位置 | 建议 |
|---|---|---|---|
| B1 | 网格页滚动区裁剪下拉框（布局 bug） | Visualization › 网格 | 修布局：滚动区内控件最小宽度约束/去掉多余 stretch |
| B2 | 草图页下半窗全空、按钮行异位 | Sketch 模块页 | 重做布局：按钮行置底、列表 stretch、补「打开根节点/打开所选」 |
| B3 | 面板高度不随内容自适应 | Viz 5 页、Part 特征 TAB、各表单 | 内容少则压缩高度，去掉固定高度/多余 stretch |
| B4 | 底部按钮行右侧大片空白 | 9 模块页、Job 设置页 | 按钮组右对齐或加弹性分隔；统一「刷新」位置 |
| B5 | 复选框莫名右缩进 | Mesh「使用示例盒」、Job「使用 mpiexec」 | 修正列布局 |
| B6 | 网格场页「实体」标签与输入框 120px 空隙 | Mesh › 网格场 | 修布局 |
| B7 | 校验结果悬空于超高空白框 | 属性编辑器/表单校验 TAB | 结果区按内容定高，筛选控件紧随其后 |
| B8 | 窗口默认尺寸不统一 | 各工作窗（生成报告页截图分辨率差一倍） | 统一各工作窗默认尺寸规范 |

### 7.3 按钮与操作区规范（P1）

| # | 问题 | 建议 |
|---|---|---|
| C1 | 按钮宽度无规则（通栏 vs 小按钮混用） | 定规范：每页唯一主操作可用通栏，其余为小按钮；同窗同层级同规格（如「刷新」一律小按钮置底行右侧） |
| C2 | 平级按钮无分组、破坏性操作无警示 | Results 页按「常规/维护/导出」分组；「移到废纸篓」等加警示色或二次确认标识 |
| C3 | 曲线页 9 按钮墙 | 导出类收进「导出 ▾」菜单，管理类收进「曲线 ▾」菜单 |
| C4 | 无数据时操作按钮全部启用 | 统一禁用策略（曲线/表格页无数据时禁用对应操作组） |
| C5 | 「拾取」一词两义 | 文件浏览类改「浏览…」，视口点选保留「拾取」 |

### 7.4 列表与空态（P1）

| # | 问题 | 建议 |
|---|---|---|
| E1 | 空态文案/位置/标点四套体系 | 统一为「暂无XX。点击上方『新建XX』创建」式引导文案，居中或列表内顶部 |
| E2 | 列表样式不一（斑马纹只载荷页有） | 统一列表控件与行样式 |
| E3 | 空列表无占位（属性参数页可选物理体、Mesh 统计表、Results 表格） | 统一空态占位 |
| E4 | 表格页「| |」分隔符错乱、筛选框无持久标签 | 信息行改用标准 label；筛选框加外部标签或 tooltip |

### 7.5 控件与命名一致性（P1/P2）

| # | 问题 | 建议 |
|---|---|---|
| N1 | 参数命名四套（dx/dy/dz、旋转原点 x、缩放中心 x…） | Mesh 窗统一为「平移 X/Y/Z」「旋转轴 X/Y/Z」式中文标签+坐标子标 |
| N2 | 「维度」下拉取值格式不一 | 统一「0 — 点 / 1 — 线 / 2 — 面 / 3 — 体 / 全部」 |
| N3 | 分组头与字段重名（标量/标量、时间/时间/t=0） | 分组头或字段改名（如字段改「变量」） |
| N4 | Part 特征 TAB 标签列宽不齐 | 统一标签列最小宽度，切换 TAB 输入框不跳动 |
| N5 | 三层嵌套页签层级不可感知 | Job 输入编辑器子页签用不同视觉层级（缩进/样式区分） |
| N6 | 同功能不同名（向量 vs Vector Arrays；分组 vs 物理组） | 建立术语表统一 |
| N7 | 属性编辑器 vs 浮动表单两套控件风格 | 统一为一套（建议保留浮动表单圆角风格，编辑器复用同一 QSS） |
| N8 | 预览文本区尺寸策略不一 | 统一最小高度+随内容伸缩 |

### 7.6 状态与反馈（P2）

| # | 问题 | 建议 |
|---|---|---|
| S1 | 禁用态三种表达（灰字/黑字可编辑/浅灰按钮） | 统一禁用视觉规范 |
| S2 | 只读模式边界不清（结构化只读 + 写出按钮并存） | 只读时禁用编辑区并加提示条 |
| S3 | 状态行格式三套（竖线/冒号/句式） | 统一「标签: 值」冒号式灰色辅助文本 |
| S4 | 生成报告 `(Physical Group=)` 空值截断观感 | 空值不输出该括注 |

### 7.7 建议实施顺序

> 图标体系引入（§8，用户已定为优先级第一）先行决策，再按下述批次执行；图标与第一批可并行。

1. **第一批（低成本高收益）**：L1/L2/L4 漏翻与双文案、B1/B5/B6 布局 bug、B2 草图页重做、C5 拾取改名。
2. **第二批（规范统一）**：C1/C2/C3 按钮规范、E1~E4 空态与列表、N1~N6 命名、B4/B7/B8 空白与尺寸。

## 8. 图标体系调研与引入方案（优先级最高，先决策后实施）

### 8.1 现状

- 工程里只有 4 个自绘 PNG（`resources/icons/`：check/dot/down-arrow×2），通过 `icons.qrc` 内嵌。
- 全部工具栏、按钮、页签、树节点均为**纯文字，无图标**（见 §1~§6 截图），这是各弹窗观感粗糙的共同原因之一。

### 8.2 Qt 技术栈下的可选方案

| 方案 | 形式 | 许可证 | Qt 集成 | 评价 |
|---|---|---|---|---|
| **QtAwesome**（[gamecreature/QtAwesome](https://github.com/gamecreature/QtAwesome)） | 图标字体（Font Awesome 6 Free，~2000 图标） | 代码 MIT；FA Free 图标 CC BY 4.0 / 字体 SIL OFL 1.1 | 2 个源文件 + 字体打进 qrc，直接 `awesome->icon(fa::fa_solid, fa::fa_xxx)` 得 QIcon | **推荐首选**。维护活跃、支持 Qt6；字形随字体缩放，天然 HiDPI；可用 QPainter 任意改色（完美适配浅色科研风 + 禁用态灰化）；商用只需署名 |
| Material Symbols（[QMaterialIcons](https://github.com/DKrepsky/QMaterialIcons)） | 可变字体（Google，多字重） | Apache 2.0 | 同字体方案 | 备选。风格更现代，但集成库小众、维护频率低；多字重优势在桌面工具栏不明显 |
| 纯 SVG 图标库（[Bootstrap Icons](https://icons.getbootstrap.com/) MIT / [Tabler](https://github.com/tabler/tabler-icons) MIT / [Phosphor](https://github.com/phosphor-icons/phosphor-icons) MIT / [Remix](https://github.com/Remix-Design/remix-icon) Apache 2.0） | 单个 SVG 文件 | MIT/Apache，最宽松 | 选中的 SVG 打进 qrc，`QSvgRenderer` 渲染 | 许可证最干净、可按需只引 30~50 个；但**换色不如字体方便**（需渲染时替换 fill 或预制双色），增删图标要重新走资源流程 |
| KDE Breeze 图标主题 | 成套 SVG/PNG | LGPLv3 / 部分 CC-BY-SA | 作为 QIcon 主题目录加载 | 桌面原生感强，但 copyleft 许可证对再分发有约束，风格偏 KDE，不推荐 |
| `QStyle::standardIcon` | 系统原生 | — | 一行代码 | 各平台外观不一致、覆盖少，不满足"统一美观"目标 |

### 8.3 推荐方案：QtAwesome（Font Awesome）+ 集中式图标工厂

**离线确认（2026-09-24 核实 [QtAwesome 仓库](https://github.com/gamecreature/QtAwesome)）**：免费版字体文件**随库直接分发**（"The free fonts are included in this project"），运行时 `initFontAwesome()` 从 Qt 资源内嵌的本地字体加载字形，**全程零网络**；官网付费套餐（截图所示 Starter/Solo/Team）只是 Font Awesome 官方 Pro 图标的 CDN 托管服务，与本方案无关。Windows/macOS 打包产品可完全无外网运行。当前 main 分支已升级 Font Awesome 7，如偏好 FA6 可用 `fontawesome-6` 分支。许可证：代码 MIT，字体 SIL OFL 1.1，图标 CC BY 3.0——商用允许，需在关于对话框或文档中署名（"Font Awesome by Dave Gandy"）。

理由：
1. **换色能力是关键**：本项目要统一浅色风格并支持禁用态/激活态着色，字体字形用 QPainter 直接着色，比 SVG 方案省事得多。
2. **单一依赖**：vendor 进 `external/QtAwesome`（2 个源文件 + 一个字体文件，走 qrc 内嵌，Windows/macOS 打包零额外步骤）。
3. **覆盖度**：FA6 Free 2000+ 图标覆盖工具栏/树节点/对话框全部场景；个别 CAE 领域专用图标（如剖分网格）找不到时可保留少量自绘 SVG 兜底。
4. **许可证**：MIT + CC BY 4.0，商用无碍，署名写进 `doc/` 或关于对话框即可。

拟议接入架构（实施时参考，本轮不动工）：

```
external/QtAwesome/            # vendored（MIT 头文件保留）
resources/icons/fa-solid-900.ttf  # 打进 qrc
src/IconFactory.cpp/h          # gmp::icons::get(Id) → QIcon
  - 集中维护「动作名 → 字形 + 语义色」映射表
  - 跟随 QApplication palette（普通/禁用/激活三态自动着色）
  - 尺寸策略：工具栏 20px、树节点 16px、按钮 icon+text 间距统一
```

替换顺序建议：① 13 个模块工作窗顶部操作按钮（§1 各页按钮行）→ ② 工具栏/回放控制 → ③ 树节点类型图标 → ④ 对话框按钮。配合 §7 的 C1~C3 按钮规范一起做，避免二次返工。

### 8.4 决策记录

1. **方案（✅ 2026-09-24 用户确认）**：QtAwesome（Font Awesome Free，字体内嵌 qrc，离线可用，署名入关于对话框）。
2. **风格基调（✅ 2026-09-24 确认）**：FA Solid 实心；小尺寸场景辨识度优先，用 scale-factor 0.9 + 灰色着色中和厚重感。
3. **排布规范（✅ 2026-09-24 确认）**：a) 图标居左、图标与文字间距 6px（Qt 默认排布，不做图标在上布局）；b) 纯图标按钮仅限国际通用语义动作（回放播放/暂停/停止/步进、新建/打开/保存/删除/刷新），其余一律图标+文字，纯图标按钮必须有中文 tooltip；c) 尺寸：工具栏 20px、按钮与树节点 16px、菜单 16px，HiDPI 随字体缩放。
4. **深色模式（✅ 2026-09-24 确认）**：本次不做深色皮肤；IconFactory 颜色一律取 `QApplication::palette()`（普通/禁用/激活三态），深色皮肤留作将来专项，图标无需返工。

### 8.5 实施范围与节奏（✅ 2026-09-24 确认）

- 一个任务连续完成四阶段替换：① 13 模块工作窗顶部操作按钮 → ② 工具栏/回放控制 → ③ 树节点类型图标 → ④ 对话框按钮。
- 每阶段一次提交 + 定向巡览验证；全量巡览在最后一阶段后执行。
- 图标替换与 §7 样式修复（第一批漏翻/布局 bug 等）**分开提交**：图标先行，样式修复第二批，避免单提交混杂布局与图标改动。
- **映射表确认方式（✅ 2026-09-24 确认）**：阶段①②的「动作→字形」映射表实施前交用户审阅一次；③树节点、④对话框由实施方按语义选定，实施后交付用户过目（人工验证手册中列明），不合意者逐个更换。
- **验收流程（✅ 2026-09-24 确认，用户修订）**：每阶段完成后——构建 + 相关定向巡览通过 + 交付**人工验证手册说明**（列明本阶段改动点与人工检查步骤），由用户人工校验并反馈，通过后再进入下一阶段；不做逐阶段全量截图对比。第四阶段全部完成后：全量巡览 + CTest + 用户最终人工过真实界面，全部通过才提交推送（分阶段提交）。
- **署名（✅ 2026-09-24 确认）**：About 对话框正文加 "Icons: Font Awesome by Dave Gandy（CC BY / SIL OFL 1.1）" + 仓库 NOTICE 文件，双落点。
- **专用图标兜底（✅ 2026-09-24 确认）**：默认全部 FA 近似字形（网格剖分/物理组等），实施后将语义牵强的 ≤5 个图标截图标出交用户逐个裁决；**FA 版本用 main 分支（FA7），锁定 commit**。
