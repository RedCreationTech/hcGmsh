## 2. Step scheme 一致性（2026-09-21-029）

### 2.1 默认值

1. 打开项目，新建一个瞬态 Step。
2. 打开 Step 的“参数”页。
3. 检查 `scheme`。
4. 点击“确定”，保存项目，再执行“同步模型到输入”。
5. 检查项目 YAML 中该 Step 的参数和生成 `.i` 的 `[Executioner]`。

预期：

```text
UI：scheme = implicit-euler
YAML：scheme: implicit-euler
.i：scheme = implicit-euler
```

### 2.2 显式选择 BDF2

1. 将同一个 Step 的 `scheme` 改为 `bdf2`。
2. 保存、同步 `.i`、关闭并重新打开项目。

预期：UI、YAML 和 `.i` 均为 `bdf2`，重开项目后不会退回默认值。

## 3. 新作业定位与制品排序（2026-09-21-030）

1. 打开 Job Workspace，先刷新出历史作业。
2. 从当前 V01 项目再提交一个远程作业。
3. 提交成功后不要手工搜索，观察作业表。

预期：新作业自动出现在第一行、被选中并滚动到可见区域；自动刷新和手工刷新后选择不丢失。

4. 作业运行完成后点击“刷新文件”。

预期制品顺序：

1. 主历史 CSV；
2. 主 Exodus；
3. `task.md`；
4. 一行 `Auxiliary Times CSV (N files)` 摘要；
5. 输入、日志和其他文件。

辅助摘要的悬浮提示应能看到原始文件名，主 `.e` 和主 CSV 不再被 101 个编号 CSV 挤到列表末尾。

## 5. 整体导入任务目录（2026-09-21-034）

### 5.1 引用原目录

1. 打开 Results Workspace。
2. 点击 `Import Task Directory...`。
3. 选择 `/Users/a123/Downloads/job_20260921_141654_2gu2ws/`。
4. 保持 `Open the main field result after import` 勾选；“Import storage”询问中选择 **Yes**，即引用原目录。

唯一主结果无需人工猜测，应自动识别并打开主 `.e`。Results 中应只有一个顶层任务包，名称类似：

```text
uniaxial_tension_single · 2gu2ws
```


取消 `Open the main field result after import` 后再次导入，预期只登记结果包，不改变当前视口。

### 5.2 完整性验证

1. 选中任务包或其任一主文件。
2. 点击 `Verify Package`。

预期提示所有清单文件的 SHA-256 验证通过。若人为修改临时副本中的文件，应明确报告具体文件的 `SHA-256 mismatch`，不能显示成功。

### 5.3 复制到项目工作区

1. 删除项目中的任务包引用；确认磁盘上的下载目录仍存在。
2. 再次导入；“Import storage”选择 **No**。

预期：任务被复制到当前项目旁的 `.work/results/job_20260921_141654_2gu2ws/`，复制完成后强制通过 SHA-256；任务包摘要显示 `project copy`。

### 5.4 失联、变化与非托管目录

1. 对临时复制的外部任务目录执行导入，然后暂时改名该目录。
2. 刷新 Results。

预期任务节点保留并标记 `missing`，不会静默移除或改指其他目录。恢复目录后重新导入即完成重新定位。

也可选中失联节点点击 `Relocate...` 并指定移动后的任务根目录；预期更新原节点，不创建第二个非托管节点。外部目录有新增、删除或大小/时间变化时，先标记 `content changed`；点击 `Rescan...` 后先显示变化摘要，再由用户确认更新。

3. 在另一个临时目录只放一份 `.e` 和一份含 `time` 的 CSV，不放 `snapshot-manifest.json`，执行目录导入。

预期：必须出现主结果/名称确认，任务持续标记 `unmanaged`；不能显示“完整性已验证”。

4. 对“复制到项目工作区”的临时结果包点击 `Trash Project Copy...`。

预期：确认框明确显示项目副本路径和大小，确认后只把 `.work/results/` 内副本移到系统废纸篓；引用的外部目录不提供此删除动作。

## 6. Results 表格（2026-09-21-031）

### 6.1 历史 CSV

1. 在任务包下单击 `uniaxial_tension_single.csv`。
2. 切换到“Table/表格”。

预期顶部显示来源、文件名、`CSV`、筛选行数/总行数；总行数为 101。默认第一页显示 100 行，第二页显示 1 行。

依次验证：

- 页大小可切换为 50、100、500、1000；
- 单击数值列头后，排序作用于全部 101 行，再分页；
- Column 选择 `Bottom_Force`，输入 Value min/max 后行数立即变化；
- Entity min/max 可限制行号范围；
- 显示格式可切换 Auto、Scientific、Fixed；Digits 默认 8，可调整；
- 清除过滤后恢复 101 行。

### 6.2 Exodus 场数据

1. 打开主 `.e`，在视口选择 `Cell: integration_microseconds`。
2. 切换若干时间步，再打开“Table/表格”。

预期表头同步显示正确的场名、`Cell` 和当前时间；600 个 Cell 可完整分页。切换为多分量场时显示 `C0…Cn` 和 `Magnitude`。`NaN/+Inf/-Inf` 过滤有明确文本与浅色状态提示，不能显示为空白或零。

## 7. Results 曲线与多结果比较（2026-09-21-032）

### 7.1 跟随视口与固定曲线

1. 打开主 `.e`，选择任一 Cell 场并进入“Plot/曲线”。

未拾取实体时，预期出现该场随时间变化的 `min/mean/max` 三条包络曲线，横轴为 Time，不得使用 Cell 编号作为横轴。

2. 启用结果 Probe，选择与场位置类型一致的 Point 或 Cell，并在视口单击一个实体。

预期曲线切换为该实体的时程，图例包含实体类型和 id。Probe 类型与当前场不一致时保持全场包络，不把 Point id 错用到 Cell 场。

3. 点击 `Pin preview`，再切换视口输出场。

预期已固定曲线保留，新场只替换“跟随视口”预览。保存并重开项目后，固定曲线配置仍存在；源文件失联时曲线配置保留但显示不可用提示。

4. 将 Probe Mode 改为 `Path points`，在模型上按路径顺序点击至少两个节点。

预期曲线模式显示 `spatial path (picked points)`；横轴为累计 `Path distance`，不是节点编号，纵轴为当前时间步所选场值。点击 `Clear` 清空整条路径；切回 Point/Cell 后不沿用旧路径。

### 7.2 导入 CSV 曲线

1. 双击任务包下的主 CSV，或在 Plot 页点击 `Import CSV...`。
2. 预览中检查编码、分隔符和行数。
3. X 轴应自动定位 `time`；Y 默认不选中。
4. 选择 `Bottom_Force`、`RP1_Force` 或 `RP1_Displacement` 后确认。

预期：曲线使用原始采样点，图例为“文件/来源 · 字段”；多次导入可叠加。UTF-8 BOM、逗号、分号、Tab 均可识别。无法从列名解析单位时，坐标轴明确显示 `unit unspecified`。列数错误或数值错误必须报告行号，只有明确选择“忽略坏行”后才能继续，且图表持续显示警告。

若两条曲线的 X 或 Y 单位冲突，页面必须明确列出冲突单位并阻止强行共轴，提示使用独立对比窗口或显式换算。

### 7.3 误差比较

1. 保证至少两条兼容曲线可见。
2. 点击 `Compare 2 curves`，明确选择 Reference 和 Candidate。

预期：仅在重叠区间、参考曲线采样点上做线性插值，不外推；新增 `Candidate − Reference` 曲线，并显示有效点数、排除点数、MAE、RMSE、最大绝对误差和 NRMSE。参考范围为零时 NRMSE 明确禁用。

### 7.4 导出

依次验证：

- PNG：可选 1×、2×、4×；
- SVG：文件可在浏览器中打开且曲线保持矢量；
- CSV：保留曲线名、来源、X/Y 字段、单位和原始双精度；
- Copy image：剪贴板可粘贴出当前可见图；
- `Edit selected`：可调整曲线名、颜色、线型、线宽和标记；
- 隐藏或移除一条曲线后，导出只包含仍可见的曲线。

## 8. 项目加载反馈与场时程正确性（2026-09-21-035/036）

### 8.1 项目重开

1. 保存当前项目，确保主 Exodus 仍是视口当前结果。
2. 关闭并重新打开项目。

预期：点击打开后立即在底部状态栏看到 `Opening project`；项目恢复只加载当前帧，不在后台静默预计算所有曲线时间步。完成时显示 `Project loaded`，不应再出现约 24 秒毫无反馈的窗口。

### 8.2 第一次构建曲线与缓存

1. 打开 Results Workspace 的 Plot 页。
2. 依次选择 `stress_zz`、`strain_zz`、`kappa_t`、`DamageT`。

预期：第一次选择字段时状态栏显示 `Building <field> history: N/101`；完成后出现时程。切换到其他字段再切回时，应直接使用缓存，不再重新扫描 101 个时间步。

### 8.3 数值与播放联动

1. 观察上述字段的 `min/mean/max` 曲线。
2. 拖动或播放时间步，同时观察云图和色标。

预期：这些实际结果字段不再全部显示为横线；云图、色标和当前时间步同步变化。`kappa_t` 在 `t=0` 可为全零，但后续时刻应出现非零值。物理上确实恒定的字段可以是横线，不能以“所有字段必须变化”作为判据。

### 8.4 表格时间步定位（2026-09-21-037）

1. 选择 `Cell: DamageT`，将主播放进度条停在第 0 步，打开 Table 页。
2. 检查 Table 顶部 `Step`、元数据中的 `Time` 和状态摘要。
3. 点击 `Latest`，再把 Table 的 `Step` 改回中间步骤。

预期：第 0 步允许 `C0` 全为 0，但摘要明确显示 `range=[0, 0]`、`nonzero=0` 和当前步全零提示；点击 `Latest` 后表格与主播放条同步到末步，`Time` 更新且部分 `C0` 非零；从 Table 修改 Step 时，主播放条、云图和表格同步刷新。

### 8.5 Results 多语言（2026-09-21-038）

1. 在“设置 → 语言”选择“中文”，重新打开 Results 工作窗并依次查看“结果、曲线、表格”。
2. 检查结果包的五类目录、托管/引用/校验状态，打开 CSV 导入、曲线编辑和曲线比较对话框。
3. 切换为 English，再检查同一批界面。

预期：中文模式下按钮、分类、状态和操作提示均为中文，English 模式下恢复英文；`DamageT` 等输出场名、CSV 列名、任务名、文件名和绝对路径保持原文，不因切换语言发生变化。曲线的 `min/mean/max` 通用后缀随界面语言切换，但字段名本身不变。
