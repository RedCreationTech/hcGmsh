# UI 重构 Phase 2 人工验收清单

> 当前验收范围：I-02“保留并优化左侧模型树”（I-01 / I-01A 已通过并关闭）
> 前置条件：Phase 1 人工验收已通过
> 当前结论：I-02 人工验收通过（2026-09-03）

## 验收准备

1. 启动 `./build/gmp_ise`。
2. 打开一个含 Material 节点的项目，或在材料根节点下新建一个材料。
3. 记住当前项目标题栏是否已带 `*`，便于检查未提交编辑是否误改保存状态。

I-02 另需准备：

1. 优先打开一个已有的 `.gmp.yaml` 项目，项目中至少有 Part、Material；如需验证舞台双向定位，Part 应由拉伸/旋转等特征产生并正在舞台显示。
2. 确保 MOOSE 设置中已经填写 `.i` 输出路径；不要求真正提交计算作业。
3. 如项目已有 Job/Result，可直接使用；否则可在对应根节点下新增临时条目完成导航验证，验收后不保存项目即可。

## TEST-P2-I01-01 单击只选择，显式命令才编辑

1. 单击一个 Material 子节点。
2. 确认节点高亮，顶部“当前对象”同步，但没有弹出编辑窗。
3. 分别用双击、`Model → 编辑属性...`或 `Enter` 打开属性窗（每次检查后取消）。

通过标准：单击不弹窗；三个显式入口打开同一类型的表单。

## TEST-P2-I01-02 弹窗语义和舞台位置

1. 双击 Material 子节点。
2. 确认标题为“编辑材料 — <对象名>”，并有“确定/取消”。
3. 确认窗口默认出现在中央舞台偏左，可拖动，舞台仍可见。
4. 在表单打开时尝试点击另一个树节点。

通过标准：表单为模态窗，处理完当前编辑前不能切换树对象；没有恢复永久右栏。

## TEST-P2-I01-03 取消、关闭和 Esc 丢弃缓冲

1. 打开表单，修改名称和至少一个参数，不点“确定”。
2. 点“取消”，确认树节点名称和参数不变，项目标题的 `*` 状态与打开前一致。
3. 再次打开并修改，分别用标题栏关闭和 `Esc`重复检查。

通过标准：三种取消方式均不写回、不产生脏状态。

## TEST-P2-I01-04 校验失败阻止提交

1. 打开表单，清空“名称”，点“确定”。
2. 确认弹窗不关闭，错误文本可见，光标定位到名称。
3. 恢复名称，对当前类型再清空一个必填参数（如 Material 的 `type`），再点“确定”。

通过标准：非法数据不写回；表单切换到对应页并尽可能聚焦首个错误字段。

## TEST-P2-I01-05 确定后一次写回

1. 打开表单，将名称改为一个不重复的合法名称，修改一个参数。
2. 在点“确定”前，观察左侧树和项目标题，确认它们未变。
3. 点“确定”。

通过标准：表单关闭后树名称、参数和当前对象同步到新值，项目标记为已修改。

## TEST-P2-I01-06 尺寸记忆、可见性与专用编辑器回归

1. 调整 Material 表单尺寸后取消，重新打开，确认同类型尺寸恢复。
2. 将表单拖到屏幕边缘后关闭，改小主窗口再打开，确认弹窗中心回到舞台可见区。
3. 双击 Sketch 和 Part 子节点，确认仍分别打开草图和部件专用编辑器。
4. 打开 Job/Results，确认仍使用各自的独立工作窗，中央舞台不被替换。

通过标准：同类型尺寸可恢复，无越界不可恢复窗口，Phase 1 既有专用编辑和独立工作窗无回归。

## TEST-P2-I01-07 模块工作窗无双层滚动

1. 依次打开 Material、Section、Step、Load、Mesh 等模块工作窗。
2. 检查窗口默认状态下的标题说明、主操作、当前对象列表和底部对象操作。
3. 缩小窗口高度后再次检查滚动行为。

通过标准：默认尺寸内主要交互均可见；主操作横向排列；Mesh 可通过“模型/几何/分组与网格场/网格/日志”切换全部功能；任一页面不出现内外并存的两条竖向滚动条；缩小时至多出现一层内容滚动。

## TEST-P2-I01-08 属性与部件编辑页签布局

1. 双击 Material 子节点，确认属性窗显示“常规/参数/校验/预览”四个页签。
2. 切换四个页签，确认字段、错误汇总和预览均可访问，底部“确定/取消”始终可见。
3. 新建或双击 Part，确认部件窗显示“拉伸/旋转/放样/扫掠”四个页签。
4. 切换四个部件页签，确认每个特征的字段和执行按钮默认可见。

通过标准：表单标签与字段同排且不被裁切；页签切换正常；没有为了访问底部按钮而使用第二条竖向滚动条。

## TEST-P2-I01-09 Job、Visualization、Results 工作窗布局

1. 打开 Job 工作窗，切换“作业列表/MOOSE 设置”。
2. 在 MOOSE 设置中依次切换“算例设置/执行配置/输入文件/运行日志”，检查底部“运行/检查输入/停止”始终可见。
3. 打开 Visualization 与 Results 工作窗，切换其全部页签。
4. 关闭并重新打开三个工作窗，确认尺寸合理且未超出当前屏幕。

通过标准：复合功能通过页签访问，默认窗口内无双层滚动、无底部操作裁切；重复打开仍为单实例且尺寸可用。

## TEST-P2-I02-01 旧项目与模型树结构兼容

1. 打开验收准备中的旧项目，展开所有根节点。
2. 确认既有对象名称和参数仍在，双击一个 Material/Part 并取消，确认编辑入口正常。
3. 确认模型树除原有层级外还包含 Assembly、Physics、Constraints、Selections、Input Cases。
4. 保存为一个新的 `.gmp.yaml`，关闭并重新打开副本。

通过标准：旧对象和参数不丢失；新增根节点可见；另存并重开后结构、对象和参数保持一致。

## TEST-P2-I02-02 Model/Results 导航与状态展示

1. 观察左侧顶部，确认只有“模型/结果”两个导航页签，没有 Material Library 空页签。
2. 在 Model 中展开几个根节点并选择一个 Part，然后切到 Results，再切回 Model。
3. 检查“对象/状态”两列：空根节点、已配置对象、网格、作业和结果均同时显示状态图标与状态文字。
4. 分别拖动 Model 与 Results 表头中两列之间的分隔线，调整对象列和状态列宽度。

通过标准：页签切换不改变项目数据；返回 Model 后原选择和合理的展开状态仍保留；状态不只依赖颜色，能区分未配置/不完整、就绪、失效、已生成、运行中、成功、失败等实际出现的状态；两棵树的列宽均可拖动调整。

## TEST-P2-I02-03 按名称过滤且不改数据

1. 在 Model 过滤框输入一个已知对象名的连续字符，大小写可与原名不同。
2. 确认匹配对象及其父节点保留，其他无关分支隐藏。
3. 确认过滤框内出现尺寸协调的小号清除图标；点击后确认完整树恢复，旁边不再显示独立的大号清除按钮。
4. 在 Results 页对 Job 或 Result 名称重复上述检查。

通过标准：过滤结果正确且不改变父子关系、对象数量、参数或项目脏状态；清除后树完整恢复。

## TEST-P2-I02-04 根节点与子节点右键菜单

1. 右键 Parts 根节点，记录菜单项。
2. 右键一个 Part 子节点，记录菜单项。
3. 再分别右键 Mesh、Jobs、Results 根节点和子节点。

通过标准：根节点提供新增、全部展开/折叠；Mesh/Jobs/Results 根节点还提供对应工作窗入口。子节点提供类型匹配的打开/编辑命令以及复制、重命名、删除；根与子菜单明显不同。

## TEST-P2-I02-05 模型树与舞台双向定位

1. 在 Model 树选择一个带有效 `gmsh_volume_tag` 且正在显示的 Part。
2. 确认中央舞台过滤/高亮到对应实体，顶部当前对象与状态栏同步。
3. 开启舞台拾取并点击该实体。
4. 如项目中有已绑定维度/tag 的 Selection，再选择该节点并拾取其 Physical Group。

通过标准：树选择能定位舞台对象；舞台拾取能返回并选中对应 Part/Feature 或 Selection。没有命名绑定时定位相应根节点并给出提示，不崩溃、不擅自创建对象。

## TEST-P2-I02-06 Input Cases 与 Results 导航

1. 执行“模型 → 同步模型到 MOOSE 输入”。
2. 回到 Model，展开 Input Cases，确认出现当前 `.i` 算例节点并标为“已生成”。
3. 切到 Results，确认 Jobs/Results 及其状态被镜像；选择一个条目，再切回 Model。
4. 双击 Job 或 Result 条目。

通过标准：Input Case 可见且随项目保存；Results 选择同步到 Model 对应节点；双击打开 Job/Results 独立工作窗，中央舞台始终保留。

## TEST-P2-I02-07 上游修改触发下游失效

1. 记下当前 Mesh、Input Cases、Jobs、Results 的状态。
2. 修改并确定一个上游对象（如 Material 参数或 Part 几何参数）。
3. 再观察上述节点状态。
4. 重新生成网格并再次同步 MOOSE 输入。

通过标准：关联 Mesh、Input Cases、非运行中的 Job 变为“失效”；历史 Results 不被改写。重新生成后 Mesh/Input Case 恢复“已生成”。正在运行/排队的 Job 不会被强行改成失效。
