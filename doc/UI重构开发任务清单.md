# GMP-ISE UI 重构开发任务清单

> 来源：`doc/UI重构需求记录.md`  
> 用途：按可逐步执行、可人工验证的粒度拆分的开发任务清单  
> 版本：2026-09-02 v2（Phase 0 准入与 Phase 1 依赖修订）

---

## 使用说明

1. 本清单按实施优先级分为 **Phase 0（基础冻结） → Phase 1（布局重构） → Phase 2（交互重构） → Phase 3（视觉与可访问性） → Phase 4（前处理工作流闭环）**。建议按顺序执行，前置任务未完成时不应启动后续强依赖任务。
2. 验收分为“自动合同验收”和“人工 UI 验收”：当前阶段尚无 UI 入口的能力，不提前要求人工验证，移入实际接入该能力的后续任务。
3. 阶段准入要求：本阶段自动测试全部通过，且本阶段明确列出的人工验收全部通过；任何一项不满足时不得标记阶段完成。
4. 任务编号前缀说明：
   - `F`：Foundation（基础合同/架构）
   - `L`：Layout（布局）
   - `I`：Interaction（交互）
   - `V`：Visual/Accessibility（视觉与可访问性）
   - `W`：Workflow（前处理工作流）
   - `M`：Milestone（端到端里程碑）

## Phase 0：数据合同与架构冻结

> 目标：在改动任何 UI 代码之前，先冻结“项目对象 → Physical Groups → MOOSE blocks → 输入快照”的数据合同、应用模板和版本策略。UI 表单不得先于映射合同各自实现。

### F-01 冻结项目模型 YAML schema v2

- **优先级**：P0
- **关联需求**：REQ-010、REQ-011、REQ-012、REQ-013
- **交付物**：
  - `doc/schema/project-v2.md`
  - `.gmp.yaml` 读写兼容策略说明
  - 新增/扩展字段清单：Assembly/Instances、Physics、Constraints、Selections/Sets、Input Case、MeshSnapshot、ApplicationProfileRef、UnitContract
- **实现要点**：
  1. 梳理当前 `.gmp.yaml` 所有字段。
  2. 在不破坏旧字段的前提下，声明新增节点类型及其 `params` 结构。
  3. 定义版本号字段与读取降级策略：未知版本报错；旧版本自动迁移；新增字段缺省值安全。
  4. 在 `src/` 中建立 `ProjectSchema` 常量/枚举或 JSON schema。
- **自动合同验收**：
  1. 递归读写 `application_profile`、`unit_contract` 和列表/嵌套字段，保证类型与结构不丢失。
  2. 新节点、节点 `status`、规范 `mesh_snapshot.summary` 和早期扁平摘要均完成往返测试。
- **人工 UI 验收**：
  1. 打开一个旧版 `.gmp.yaml` 项目，确认能正常加载和保存，且既有业务数据无差异。
  2. 使用新 schema 创建一个包含 Assembly、Physics 节点的测试项目，关闭后重新打开，确认字段完整恢复。
  3. 检查保存后的 YAML 包含 `schema_version` 字段。

### F-02 设计应用档案（Application Profile）注册表

- **优先级**：P0
- **关联需求**：REQ-013、REQ-014、REQ-016
- **交付物**：
  - `templates/moose/profiles/` 目录结构
  - 至少 3 个 profile 文件示例：`DamSafetyApp-opt.json`、`blackbear-opt.json`、`combined-opt.json`
  - 注册表加载器：`ApplicationProfileRegistry` 类或等价模块
- **实现要点**：
  1. 每个 profile 至少包含：应用标识、可执行程序、版本/提交号、计算环境、支持的物理场与对象类型、`.i` 映射注册表、校验命令、兼容性级别、求解单位合同。
  2. 支持从文件/目录加载；profile 变更后 UI 可刷新。
  3. 区分 `production`、`prototype`、`unsupported` 支持级别；production 才默认允许提交。
  4. 与项目模型关联：项目记录 `active_profile_id`、profile 版本、映射注册表版本。
- **自动合同验收**：
  1. 3 个示例档案通过字段、支持级别、单位合同及映射版本校验。
  2. 损坏单个 profile 时保留其他有效档案，并返回可读错误。
- **后续集成验收**：应用选择、切换持久化和 UI 错误提示移入 L-04/W-07，不作为 Phase 0 人工准入项。

### F-03 设计版本化 MOOSE 类型/参数映射注册表

- **优先级**：P0
- **关联需求**：REQ-013、REQ-014
- **交付物**：
  - `templates/moose/mapping-v1.json` 或等价格式
  - 注册表读取与版本校验接口
  - 覆盖的 block 类型：Variables、ICs、Kernels/Physics、AuxVariables、AuxKernels、Materials、BCs、Functions、Constraints、Contact/Interface、Executioner、Preconditioning、Postprocessors、VectorPostprocessors、Outputs
- **实现要点**：
  1. 对每个 block 类型，定义对象类型、必需参数、可选参数、枚举值、默认值、值格式、单位量纲、适用维度。
  2. 提供稳定的排序规则，避免生成顺序随机漂移。
  3. 表单、校验器和 `.i` 生成器共用同一份注册表定义，禁止各自硬编码。
  4. 注册表带版本号；与 profile 关联。
- **自动合同验收**：
  1. 注册表覆盖基线 blocks，排序项全部指向已声明 block。
  2. 版本、对象 schema、必需参数或排序损坏时拒绝加载并返回可读错误。
- **后续集成验收**：表单热更新和生成能力禁用移入 I-01/W-03，不作为 Phase 0 人工准入项。

### F-04 冻结 Physical Groups 语义契约

- **优先级**：P0
- **关联需求**：REQ-012
- **交付物**：
  - `doc/contracts/physical-groups.md`
  - `PhysicalGroupManifest` 数据结构
  - `.msh` 物理组读取/持久化接口
- **实现要点**：
  1. 明确体组 → MOOSE `block`/`subdomain`；面/线/点组 → `boundary` 或选择集。
  2. 要求名称项目内唯一、用户可读；禁止直接以 Gmsh entity tag 作为持久化绑定键。
  3. 定义 `.msh` 生成后必须保存的摘要：物理组清单、维度、名称、实体数量、网格维度、单元类型、单元数、质量摘要。
  4. 定义几何/装配变化后物理组失效的检测与报错机制。
- **自动合同验收**：名称、维度、tag、空组、重复组、网格路径和 SHA-256 的错误条件均能阻断有效状态。
- **后续集成验收**：`.msh` 自动提取、表单选择和 stale 传播移入 W-02/W-05，不作为 Phase 0 人工准入项。

### F-05 设计输入快照（Input Snapshot）与 manifest.json 合同 v2

- **优先级**：P0
- **关联需求**：REQ-016、REQ-017
- **交付物**：
  - `doc/contracts/input-snapshot-v2.md`
  - 快照生成器接口：包含 `.i`、`.msh`、extra files、`manifest.json`
  - manifest 字段清单：项目/案例标识、文件 SHA-256、模板/映射版本、生成时间、目标求解程序、推荐命令、文件角色、单位合同、比例因子、生成器版本、基础模型哈希、扩展层哈希、最终 `.i` 哈希、`input_mode`
- **实现要点**：
  1. 明确快照目录结构；所有相对路径在快照根目录下可解析。
  2. 为每个文件标记角色：`input_mesh`、`input_config`、`result`、`initial_state`、`restart_data`。
  3. 快照一旦创建即只读；UI 编辑后再次生成产生新版本。
  4. 与现有 LIMS Facade/SimClient 提交合同兼容，新增字段版本化且向后兼容。
- **自动合同验收**：
  1. 合法快照包含 `.i`、`.msh`、附件、角色、SHA-256 和 v2 manifest。
  2. 缺文件、绝对路径、`..` 穿越、覆盖已有快照均失败。
  3. `.e` 仅在显式标记为 `input_mesh`、`initial_state` 或 `restart_data` 时允许作为输入。
- **后续集成验收**：通过 UI 生成、复制运行及 SimClient 提交移入 W-07，不作为 Phase 0 人工准入项。

## Phase 1：布局重构（P0）

> 目标：取消永久右侧栏，放大中央舞台；将顶部拆分为菜单—图标工具组—工作上下文条；建立舞台左侧垂直工具栏；支持工具组拖拽/浮动/磁吸。

- **优先级**：P0
- **关联需求**：REQ-007
- **交付物**：`doc/ui-migration-map.md`，列出全部 `property_stack_->addWidget(...)` 页面、当前入口、临时承载和最终承载。
- **实现要点**：在调整父容器前完成清点；每个旧页面必须有可执行的回归步骤和迁移负责人。

### L-01 建立两栏主工作区与兼容承载窗口

- **优先级**：P0
- **关联需求**：REQ-001、REQ-007
- **交付物**：
  - 主窗口两栏布局壳：左侧模型树 + 始终显示的中央舞台
  - 旧右栏页面的临时兼容工作窗，迁移完成前不得删除其入口
- **实现要点**：
  1. 修改 `src/MainWindow.cpp` 中 `main_split`、`property_panel`、`property_stack_`、`vertical_split` 的创建与布局逻辑。
  2. 先将 `property_stack_` 放入可恢复的兼容工作窗；不得直接销毁仍被页面和信号引用的父容器。

### L-04 重构顶部为“菜单栏—图标工具组—工作上下文条”三层结构

- **优先级**：P0
- **关联需求**：REQ-003
- **交付物**：
  - 标准菜单区：File、Model、View、Mesh、Job、Tools、Settings、Help
  - 多个紧凑常用图标工具组
  - 工作上下文条：模块选择器、当前模型/项目、当前对象
- **实现要点**：
  1. 菜单项、快捷键、工具栏按钮复用同一 `QAction` 或同一命令源。
  2. 原 13 个等宽模块页签改为工作上下文条中的“模块”紧凑选择器。

     - 模块：主动切换 Sketch、Part、Material、Mesh、Job、Visualization、Results。
     - 当前模型/项目：单模型阶段只读显示。
     - 当前对象：随模块动态变化，与模型树选择同步；不存在时显示“未选择”。
  4. 高频命令按“项目 / 编辑 / 建模 / 网格 / 作业”分成多个可独立移动的按钮组。
- **人工验证**：
  1. 逐层检查顶部为：菜单栏 → 图标工具组 → 工作上下文条，三层合计高度控制在 80–100 px。

  3. 从树选择对象，确认工作上下文条的“当前对象”同步更新；从工作上下文条选择对象，确认树同步定位。
  4. 使用菜单和快捷键执行保存、撤销、生成网格等命令，确认与工具栏按钮状态一致。

### L-05 实现工具组拖拽、浮动、磁吸与布局持久化

- **优先级**：P0
- **关联需求**：REQ-004、REQ-010
- **交付物**：
  - 可拖拽工具组容器
  - 舞台右上角预置浮动位置
  - 停靠区：顶部、底部、舞台左侧、舞台右侧
  - 布局持久化文件与版本号
- **实现要点**：
  1. 每个工具组提供拖拽手柄；整组移动，组内顺序不变。
  2. 接近合法停靠边缘或相邻组时显示吸附预览；磁吸距离 8–16 px。
  3. 浮动组不得拦截透明/空白区域下方的 VTK 交互；拖动期间暂停舞台拾取。
  4. 浮动组不得移出屏幕可恢复范围；多屏/DPI 变化后越界组自动移回主窗口可视区。
  5. View/工具栏菜单可显示/隐藏任意工具组，并提供“恢复默认布局”。
  6. 布局配置带版本号；损坏或不兼容时回退到默认布局。
- **人工验证**：
  1. 将“显示/隐藏/隔离”组拖到舞台右上角释放，确认磁吸对齐且不遮挡方向标。
  2. 拖拽期间在舞台区域移动鼠标，确认相机不旋转/不平移；释放后拾取恢复。
  3. 将工具组拖回顶部停靠区，确认吸附正确。
  4. 隐藏一个工具组，确认 View 菜单中对应项状态同步；再显示，确认恢复。
  5. 执行“恢复默认布局”，确认所有工具组回到预置位置。
  6. 手动编辑/损坏布局配置文件后启动应用，确认能安全启动并使用默认布局。
  7. 重启应用，确认上次有效布局恢复。

## Phase 2：交互重构（P0–P1）

> 目标：用浮动表单替代右侧 PropertyEditor；保留并优化模型树；统一模块、树、表单与舞台状态；完成旧右栏功能迁移。

### I-01 实现浮动属性表单与编辑缓冲

> 实施状态：已完成；2026-09-02 自动回归与人工验收通过。

- **优先级**：P0
- **关联需求**：REQ-005、REQ-006
- **交付物**：
  - `FloatingPropertyForm` 组件
  - 编辑缓冲/快照机制（确定/取消语义）
  - 默认在舞台中央偏左打开，支持移动，标题包含动作和对象名
- **实现要点**：
  1. 单击树节点只选择、定位和更新上下文；双击或“编辑”命令打开模态浮动表单。
  2. 弹窗内维护编辑副本；点击“确定”后校验并一次性写回，点击“取消”/关闭/`Esc` 丢弃修改。
  3. 字段变化不再即时写回节点；未确定修改不标记项目为已修改。
  4. 校验失败时阻止提交并定位首个错误字段。
  5. 支持“应用”按钮的场景限于材料预览、显示参数等确需连续观察结果的情况。
  6. 记忆各类型表单尺寸；位置越界时在当前舞台内重新居中。
- **人工验证**：
  1. 单击一个 Material 节点，确认仅高亮和同步上下文，不弹窗。
  2. 双击该节点，确认浮动表单打开，标题为“编辑材料 — Material-1”。
  3. 修改一个字段但不点击确定，切换树节点，确认弹出提示要求先处理当前编辑或不允许切换。
  4. 点击“取消”，确认模型树中该节点字段未改变，项目未标记为已修改。

  - 结构校验：网格存在/未过期、物理组有效、材料已指派、变量与方程完整、BC/Load/Contact 选择集存在、Step/Executioner 完整、输出变量受支持、引用可解析
  - 语义校验：区域维度匹配、约束冲突、未使用对象、单位/量纲提示、应用不支持类型、Step 策略、网格/物理维度一致
  - 错误/警告/提示分级与跳转
  - `--check-input` 调用集成
- **实现要点**：
  1. 校验器读取映射注册表，按 block 类型逐项校验。
  2. 错误阻止提交；警告需要用户确认或显式豁免。
  3. 点击问题可跳转到对应树节点和表单字段。
  4. `.i` 生成后执行内部语法/映射校验；本地有 MOOSE 可执行程序时自动执行 `--check-input`。
  5. “Workflow ready” 必须通过所有阻断校验。
- **人工验证**：
  1. 创建一个合法案例，确认“Workflow ready”为真，生成 `.i` 后 `--check-input` 通过（本地有 MOOSE 时）。
  2. 删除材料指派，确认校验报错并定位到对应 Section/Material 节点。
  3. 重命名 Physical Group 后不重生成网格，确认 `.i` 生成时校验报错并定位问题。
  4. 使用目标应用不支持的 Contact 类型，确认校验提示“不支持生成”并阻止提交。

### W-06 生成可复现的计算案例包

- **优先级**：P0
- **关联需求**：REQ-016
- **交付物**：
  - 快照生成器：`.i` + `.msh` + extra files + `manifest.json`
  - 只读快照目录；再次生成产生新版本
  - 追溯关系：当前项目状态 → 输入快照 → 作业 ID → 结果文件
- **实现要点**：
  1. 生成快照时拷贝/打包所需文件；计算所有文件 SHA-256。
  2. manifest 包含第 F-05 条中规定的全部字段。
  3. `.i` 中相对路径在快照根目录下可解析。
  4. 快照提交后不可被 UI 编辑原地修改。
  5. UI 支持查看从项目状态到结果文件的追溯链。
- **人工验证**：
  1. 生成快照，检查目录结构符合预期；检查 manifest 字段和哈希正确。
  2. 将快照复制到干净目录，按 manifest 命令运行（本地有 MOOSE 时），确认不依赖原项目路径。
  3. 修改项目后再次生成快照，确认产生新版本，旧快照内容不变。
  4. 在 Jobs 节点中查看快照版本，确认可追溯。

### W-07 与现有作业系统形成提交和结果闭环

- **优先级**：P0
- **关联需求**：REQ-017
- **交付物**：
  - 标准操作链入口：生成网格 → 装配 `.i` → 校验 → 创建快照 → 提交作业
  - 一键入口（前置条件满足时启用）
  - 远程提交上传 `.i`、`.msh`、附件
  - 作业状态/日志/结果回写
- **实现要点**：
  1. 标准链可分步执行，也提供一键入口。
  2. 远程提交直接上传文件，不要求本地有 MOOSE 可执行程序。
  3. Jobs 节点显示排队、运行、成功、失败、取消状态，记录快照版本、计算节点/队列、并行配置、起止时间、日志入口。
  4. 失败时保留生成报告、预检结果、stdout/stderr；重试默认复用原快照。
  5. 作业完成后自动登记 Exodus/CSV/日志 Results 节点，并保留追溯到 Job、`.i`、网格、项目版本的能力。
- **人工验证**：
  1. 使用合法案例，按分步入口依次执行：生成网格 → 装配 `.i` → 校验 → 创建快照 → 提交作业，确认每一步状态正确。
  2. 一键入口仅在所有前置条件满足时可用；破坏任一条件时按钮禁用并提示原因。
  3. 提交远程作业后，在 Jobs 节点查看状态更新、日志入口。
  4. 作业完成后，确认 Results 节点自动登记，且可追溯回输入快照版本。

## Phase 5：端到端里程碑验收

> 目标：以 Word 参考案例“混凝土立方体 + 钢板”建立端到端可运行基准，分阶段验证高级能力真实运行。

### M-01 里程碑 1：线弹性 + 面—面接触 + 位移加载

- **优先级**：P0
- **关联需求**：REQ-011～REQ-017、关键决策 5
- **交付物**：
  - 可运行的 Word 参考案例 v1
  - 目标应用检查通过
  - 至少完成一次本地/远程计算
- **通过标准**：
  1. 建立三维混凝土块与钢板。
  2. 定义线弹性材料并指派给 Physical Volumes。
  3. 装配实例到接触位置。
  4. 创建 Static Step、Executioner、Solver 配置。
  5. 配置可配置摩擦面—面接触。
  6. 固定底面；在钢板加载面施加位移。
  7. 配置位移/应力/应变/接触量/反力输出。
  8. 生成 `.msh` 和 `.i`，通过 `--check-input`。
  9. 提交并运行，生成 Exodus/CSV/日志结果。
- **人工验证**：
  1. 重复生成 `.i` 两次，`diff` 无差异。
  2. 在目标 MOOSE 应用中执行 `--check-input`，无错误。
  3. 运行计算，确认成功完成且结果文件可加载到 Visualization。
  4. 检查结果可追溯到输入快照。

### M-02 里程碑 2：参考点与运动耦合真实映射

- **优先级**：P1
- **关联需求**：REQ-011～REQ-013、关键决策 5
- **交付物**：
  - Reference Point + Coupling Constraint 真实 MOOSE 映射
  - 验证位移和合力传递
- **通过标准**：
  1. 创建参考点并将其与顶面运动耦合。
  2. 生成 `.i` 中对应 Constraint 对象真实存在且参数正确。
  3. 不得用整面统一位移静默冒充参考点耦合。
  4. 运行计算并验证参考点与耦合面位移一致、反力可输出。
- **人工验证**：
  1. 检查生成的 `.i`，确认 Constraint 类型不是 DirichletBC 或简单的统一位移。
  2. 运行后比较参考点和耦合面的位移/反力输出，确认传递关系正确。

### M-03 里程碑 3：CDP/认可的混凝土损伤塑性模型真实运行

- **优先级**：P1
- **关联需求**：REQ-011～REQ-013、关键决策 5
- **交付物**：
  - CDP 或所选应用认可的混凝土损伤塑性材料模型接入
  - 参数来源追踪、单位检查、基准对比报告
- **通过标准**：
  1. 混凝土材料使用 CDP 或应用认可的高级损伤塑性模型。
  2. 参数来源和单位为显示单位 → 求解单位转换后的值。
  3. 生成 `.i` 通过 `--check-input`。
  4. 运行 Word 参考案例完整流程并达到与基准相当的力-位移响应。
- **人工验证**：
  1. 检查 `.i` 中混凝土材料类型为真实损伤塑性模型，无占位参数。
  2. 运行计算，与基准曲线对比，确认趋势和量级一致。
  3. 检查生成报告中的单位转换记录与 manifest。
