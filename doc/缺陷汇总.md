## 2026-09-02-001 舞台工具栏占位图标、部分命令无响应及点击部件异常退出

- **影响接口/模块**：Phase 1 / L-03；`StageLeftToolbar`、`VtkViewer` 舞台命令、模块页签与模型树点击路径。
- **现象**：舞台左侧按钮仅显示 `R/P/Z/S/F...` 等开发期字母；加载网格后部分按钮没有可见响应；用户点击“部件”后进程曾以 `std::length_error: vector` 未捕获异常退出。启动日志中的 `vtkOrientationMarkerWidget` 与 macOS IMK 警告先于异常出现，但现有证据不足以将其认定为直接根因。
- **复现步骤**：
  1. 启动 `./build/gmp_ise`，观察舞台左侧工具栏。
  2. 加载 `.msh`，点击“显示方式”、拾取、剖切及视图按钮。
  3. 点击顶部“部件”页签；重复点击当前“部件”页签；选择模型树 `Parts` 根节点和部件子节点。
- **根因**：
  1. L-03 实现错误地把字母占位延后到 Phase 3，违反 L-03 已明确的“图标为主”验收要求。
  2. “显示方式”统一修改 Exodus 使用的 `repr_combo_`；`.msh` 模式下该控件被禁用，实际网格显示由 `show_faces_` / `show_edges_` 控制，因此命令对网格无效。
  3. 空舞台或模式不支持时命令静默返回，没有禁用原因或状态反馈，造成按钮失效观感。
  4. VTK 左键观察器在正常交互样式已接收事件的同时，手动再次调用 `OnLeftButtonDown()`，存在重复事件分发和重入风险。该问题已确认不安全并修复；但用户报告的单次 `std::length_error` 在当前环境尚未稳定复现，不能把它声明为唯一直接根因。
  5. 原 19 步 GUI 巡览仅调用 `setCurrentIndex()`，未发出真实 `tabBarClicked`，也未覆盖模型树 Parts 选择，导致点击路径回归缺口。
- **关联逻辑/路径**：`src/StageLeftToolbar.cpp`、`include/gmp/StageLeftToolbar.h`、`src/VtkViewer.cpp`、`include/gmp/VtkViewer.h`、`src/MainWindow.cpp::run_screenshot_tour`。
- **修复方案**：
  1. 使用项目自绘 20 px 图标替换全部字母占位，保留 Tooltip、可访问名称、互斥选中态和 36×34 px 热区。
  2. `.msh` 的显示方式改为“表面 → 线框 → 表面 + 边线”循环；`.e` 继续复用结果表示模式。
  3. 舞台选择在 `.msh` 映射为网格 Pick、在 `.e` 映射为 Probe；剖切在非 `.msh` 模式明确提示不可用；所有舞台命令增加状态栏/消息区反馈。
  4. 拾取/草图接管左键时中止事件继续传播；普通相机交互只由 VTK 交互样式处理，不再手工重复调用。
  5. GUI 巡览增加真实页签点击、重复点击当前 Part、Parts 根/子节点选择及 12 个舞台按钮点击。
- **验证结果**：构建通过；CTest `1/1` 通过；带 `out/box.msh` 和空舞台两种条件下的真实点击 GUI 巡览均完成 34 步，包含 Part 页签首次/重复点击、Parts 根/子节点与全部通用舞台按钮，进程正常退出；空舞台命令均给出原因提示。2026-09-02 用户确认人工回归通过。
- **状态**：已修复

## 2026-09-02-002 新建或双击草图未显示编辑工作窗

- **影响接口/模块**：Phase 1 兼容工作窗、Sketch 模块、模型树 Sketches 节点与 2D 草图编辑会话。
- **现象**：点击“新建草图”后树中能生成节点、舞台左侧出现草图工具，但没有可见的草图编辑工作窗；双击模型树中的草图也不显示编辑窗。
- **复现步骤**：
  1. 进入“草图”模块并点击“新建草图”。
  2. 关闭可能存在的 Module Workspace，在模型树中双击任一 Sketches 子节点。
  3. 观察舞台与浮动工作窗状态。
- **根因**：
  1. `open_sketch_editor` 仅建立 `SketchDocument` 会话、切换 VTK 2D 模式和调用 `SketchPanel::set_editing(true)`，未显示承载 `SketchPanel` 的 `module_work_window_`。
  2. 新建入口只调用 `add_child_item`，依赖树选择信号间接进入编辑，没有统一执行“创建并打开”。
  3. 模型树未连接 `itemDoubleClicked`；旧逻辑反而在单击 Sketches 子节点时自动进入编辑，与 REQ-005 的“单击选择、双击编辑”不一致。
  4. SketchPanel 内部列表的双击处理错误跳转到 Property 模块，没有调用草图编辑入口。
  5. 编辑态与管理态同时占用同一纵向布局，编辑控件位于列表下方，即使工作窗显示也不易被发现。
- **关联逻辑/路径**：`src/MainWindow.cpp` 中草图会话、新建入口、模型树信号和 GUI 巡览；`src/SketchPanel.cpp`、`include/gmp/SketchPanel.h`。
- **修复方案**：
  1. 建立统一 `create_and_open_sketch` 路径，新建后立即选中节点并打开编辑会话。
  2. `open_sketch_editor` 显示、置前并激活 Module Workspace，标题关联当前草图；完成编辑或关闭窗口时保存、退出 2D 并隐藏工作窗。
  3. 树单击只同步选择和 Sketch 上下文；树双击、SketchPanel 列表双击和“打开编辑”统一调用 `open_sketch_editor`。
  4. SketchPanel 分为管理态与编辑态；编辑时隐藏管理列表，从工作窗顶部直接显示绘图、约束、尺寸、撤销/重做和完成编辑控件。
  5. GUI 巡览增加新建打开、关闭、树双击重开和再次关闭四条真实交互路径。
- **验证结果**：构建通过；CTest `1/1` 通过；38 步真实点击 GUI 巡览正常退出。截图确认“新建草图”和“树双击草图”均显示编辑工作窗，且编辑控件从窗口顶部直接可见。2026-09-02 用户确认人工回归通过。
- **状态**：已修复

## 2026-09-02-003 完成草图编辑后舞台内容消失且部件编辑窗未打开

- **影响接口/模块**：Phase 1 兼容工作窗、Sketch 2D 会话、Part 模块、模型树 Sketches/Parts 子节点。
- **现象**：草图编辑时图元可见，点击“完成编辑”后树仍选中当前草图，但舞台内容被清空；点击“新建部件”或双击 Parts 子节点时没有稳定显示部件编辑工作窗。
- **复现步骤**：
  1. 新建或双击草图，绘制圆或直线后点击“完成编辑”。
  2. 观察当前草图仍被选中，但舞台图元消失。
  3. 新建部件并选择来源草图，或双击模型树中的 Parts 子节点。
  4. 观察 Module Workspace 是否显示并置前 Part 页面。
- **根因**：
  1. `close_sketch_editor` 保存后直接调用 `set_sketch_document(nullptr)`，该 API 会隐藏所有草图 actor 并恢复 3D 场景；树选择未变化，因此出现“选中对象与舞台展示不一致”。
  2. Viewer 只有“可编辑草图文档”与“无草图”两态，没有完成编辑后的只读预览态；若直接保留原指针又会在释放编辑文档后产生悬空指针风险。
  3. Part 的顶部新建入口仍走通用 `add_item_under_root`，模块页新建虽选择了来源草图，但创建后没有显示工作窗；Parts 树双击也没有专用处理，只存在默认的属性跳转语义。
  4. 部件名按固定/计数后缀生成时未检查现有同名节点，历史入口混用后可能生成重复名称。
- **关联逻辑/路径**：`include/gmp/VtkViewer.h`、`src/VtkViewer.cpp` 草图会话；`src/MainWindow.cpp` 草图关闭/选择、部件创建/打开和 GUI 巡览。
- **修复方案**：
  1. Viewer 新增拥有文档副本的只读草图预览态；完成编辑时先复制快照再释放编辑文档，保留 actor 与 2D 取景。
  2. 只读态阻断鼠标绘制、Delete、工具切换、几何约束和尺寸修改；选择另一个草图时切换预览，离开 Sketch 模块时清除预览并恢复原 3D 场景。
  3. 建立统一 `open_part_editor`，新建、Parts 树双击、部件列表双击和“打开所选部件”均切到 Part 页面、同步选择并显示/置前工作窗。
  4. 顶部与模块内“新建部件”统一执行来源草图选择、唯一名称生成、节点创建和立即打开。
  5. GUI 巡览加入实际图元、只读预览状态/实体数量断言、Parts 双击标题断言以及自动确认来源草图的新建部件路径。
- **验证结果**：构建通过；CTest `1/1` 通过；带 `out/box.msh` 的真实点击 GUI 巡览通过新增的草图预览、Parts 树双击和新建部件断言并正常退出。2026-09-02 用户确认 `TEST-P1-L03-07` 人工回归通过。
- **状态**：已修复

## 2026-09-02-005 浮动弹窗沿用旧右栏布局并出现双竖向滚动条

- **影响接口/模块**：Phase 2 / I-01、I-01A、I-04；Module Workspace、FloatingPropertyForm、PartFeaturePanel、Mesh/Gmsh、Job/MOOSE、Visualization、Results 工作窗。
- **现象**：材料等模块弹窗仍按原右侧属性栏的窄列方式纵向堆叠；外层工作窗和页面内容各有一条竖向滚动条，主要按钮、列表和底部操作不能在默认尺寸内同时看到；Job 的路径、网格、运行、输入、日志全部堆在一列，窗口会被内容尺寸撑高。
- **复现步骤**：
  1. 打开 Material Workspace，观察右边缘存在内外两条竖向滚动条。
  2. 依次打开 Part、Section、Step、Load，观察主操作纵向排列、内容留白与底部按钮裁切。

- **修复方案**：
  1. 移除 Module Workspace 的外层与模块页内部滚动容器，主操作横排，对象列表自适应，对象操作固定在底部；自动断言禁止嵌套 `QScrollArea`。
  2. PropertyEditor 拆为“常规/参数/校验/预览”四页签；PartFeaturePanel 拆为“拉伸/旋转/放样/扫掠”四页签；宽窗表单恢复标签与字段同排。
  3. Job 拆为“作业列表/MOOSE 设置”，MOOSE 设置再按“算例设置/执行配置/输入文件/运行日志”分区，运行操作固定在底部。
  4. Mesh/Gmsh 拆为“模型/几何/分组与网格场/网格/日志”，长表单仅在所属任务页保留单层按需滚动。
  5. Visualization、Results 去除无必要的外层滚动；升级相关窗口几何配置键，首次打开采用新默认尺寸并限制在可用屏幕内。
- **验证结果**：构建通过；CTest `1/1` 通过；标准 GUI 截图巡览 19 步通过；带 `out/box.msh` 的真实点击 GUI 巡览 52 步全部通过。截图确认 Material、Part、Property、Mesh、Job、Visualization、Results 默认状态无双层竖向滚动，主要交互均可通过当前页或页签访问。2026-09-02 用户确认人工验收通过。
